# LibreKO Classic UI

## Requires the canbolayir/LibreKO fork

> [!IMPORTANT]
> **This plugin does not work with the unmodified [ZeusAFK/LibreKO](https://github.com/ZeusAFK/LibreKO) client.**
> Use the **[canbolayir/LibreKO fork](https://github.com/canbolayir/LibreKO)**, which includes the required Classic UI APIs and interaction fixes.
> Deploy its matching client and server together, and build the plugin against that fork's `LibreKO.dll`. Copying the plugin into an upstream client does not provide those changes.

An editable Knight Online 1.298 Classic theme for LibreKO, with distinct Human and Karus artwork and modern native game features. Source adapters and declarative geometry remain editable; imported UIF layouts serve as artwork and visual references.

## Compatible client

The required fork provides native bridges for character pages, NPC portraits, bag quantities, chat/Info, trade approvals and merchant interactions. Some changes also affect client/server packets and inventory synchronization, so an upstream server is not a supported substitute for the matching fork server.

Latest verified pair: fork [89a595b](https://github.com/canbolayir/LibreKO/commit/89a595b960543f8d2b0efac783f41b86c2d79bd8) and the complete market-history/plugin integration on this branch, with upstream `28112ee` integrated. Deploy its matching client/server and generated content together. These are verified revisions, not a promise that every future combination will work. The manifest's `minClientVersion` alone cannot identify the required fork or API set. Enable one UI theme at a time.

See [NPC service changes and compatibility](docs/npc-services-integration.md) and the fork's [integration guide](https://github.com/canbolayir/LibreKO/blob/main/docs/classic-integration.md).

## Build and install

Requires .NET SDK 9 and 10, Godot 4.7.2 Mono, and a built compatible `LibreKO.dll`.

```powershell
dotnet build KnightOnlineUiClassic.csproj -c Release -p:LibreKOClientDir="<folder containing LibreKO.dll>"
./build.ps1 -ClientDir "<folder containing LibreKO.dll>" -InstallDir "<client>/plugins/knightonline-ui-classic"
```

The build script's defaults describe the original Windows workspace; pass both paths on another machine. Restart the client, enable **1298 Classic UI** in Settings → Plugins, and restart. A single-launch theme override is `LibreKO.exe -- theme=knightonline-ui-classic`.

## Features and implementation

- Live Character Report, Quest, Clan and Friend pages with native permission/action checks.
- Fixed-scroll NPC speech, cached circular portraits and two-column hunt/collect/reward cards.
- Class-base-aware stat presets and aligned skill requirements/descriptions.
- Contiguous equipment/costume/bag panels, common item/count borders and clipped weapon effects.
- Original-style vendor quantity/approval, twelve-slot trade and explicit final trade approval.
- Selling/Buying merchant workflows, modern search/advert features and Silver/Copper signs.
- Classic chat/Info and PM behavior, channel/item-link options, HUD coordinates/map name and rotating hotbars.
- Native Power-Up Store carts/discounts/gifts and mail attachments with Classic button artwork.
- Original Anvil artwork, aligned embedded inventory, live weight/coins, recipe-backed material placement and success/failure animation sequences.

`src/Layout` and named `*Layout.cs` files define geometry. `src/Windows` composes controls over game services. `assets/theme.json` supplies font/layout tuning. `assets/layouts` is imported reference data, regenerated by the importer; optional overrides live in `assets/overrides`.

Build the independent Godot harness with:

```powershell
dotnet build preview/Preview.csproj -p:LibreKOClientDir="<folder containing LibreKO.dll>"
$env:LIBREKO_AUDIT_CLIENT_PACK = "<client>/LibreKO.pck"
godot --path preview -- <audit arguments>
```

Use the available argument routes in `preview/Preview.cs`; the original workspace routes expect sibling `build` and `research` directories and installed content packs. These are not shipped as binaries. Transactions are checked by native domain/protocol tests and fixture interactions; the harness does not perform live player-to-player transactions.
